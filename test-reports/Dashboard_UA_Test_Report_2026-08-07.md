# Звіт про тестування

## Назва тестування
Модуль **Dashboard** — повна QA-сесія: порівняння з Figma, UI/UX-перевірка (Desktop + Mobile), функціональне тестування, перевірка даних, порожні та заповнені стани, edge-кейси, діагностика браузера.

## Загальна інформація
- **Дата:** 07.08.2026
- **Час:** Одна безперервна сесія, ~2 години
- **Середовище:** Production (продакшн)
- **Версія білда:** Недоступна — застосунок ніде в інтерфейсі не показує номер білда/версії (той самий пробіл, що й у попередніх звітах).
- **Браузер/Пристрій:** Chromium (headless, Playwright MCP) для роботи із застосунком; окремий, реальний, авторизований Chrome (Browser MCP extension) — для спроби доступу до Figma. Перевірено два viewport: Desktop (1440×900) та Mobile (390×844, клас iPhone).
- **URL середовища:** https://frontv2.getlaunched.io
- **Тестові дані:**
  - Новостворений проєкт **"QA Empty State (2026-08-07)"** (`/project/019fdbaa-1d51-727a-9153-b79f4f6c0f45`) — для перевірки порожніх станів.
  - Найбільш заповнений існуючий проєкт **"Dior Brand"** (`/project/019dfc93-1e50-70f3-ac16-7c8c5dd1e6c9`) — обраний після перегляду всіх 7 проєктів акаунта (Tea, Dior Brand, test ×3, Premium, test 3) як такий, що має найбільший обсяг реальних даних у кожному модулі (продукти, клієнти, конкуренти, ризики, дії, локації, постачальники).

## Обсяг тестування
- Перегляд попередніх звітів (`Dashboard_Test_Report_UA.md` від 06.08.2026, `PROJECT_KNOWLEDGE.md`, `BUG_PATTERNS.md`) для продовження, а не повторення попередньої роботи.
- Спроба порівняння живого UI Dashboard (Desktop + Mobile) з Figma — цього разу через **Figma Dev Mode / панель Properties** у справжньому автентифікованому браузері, а не лише текстовий WebFetch.
- Створення нового порожнього проєкту та перевірка всіх 7 порожніх станів віджетів.
- Повна перевірка заповненого Dashboard на проєкті "Dior Brand": усі 7 віджетів, шапка проєкту, кнопка Invite, глибокі посилання, узгодженість фінансових показників з повною сторінкою Forecasts & Reports.

## Важливе обмеження — піксельне порівняння з Figma досі неможливе, але вдалося отримати реальні структурні дані

На відміну від сесії 06.08.2026 (де WebFrame повертав абсолютно порожній результат за посиланнями на Figma), цього разу було використано **справжній, автентифікований браузер** (Browser MCP-розширення) із реальним доступом до Figma-файлу. Це дало доступ до:
- реальних коментарів команди дизайну на полотні (123 непрочитаних коментарі — файл активно доопрацьовується);
- панелі **Properties** (Design Mode), яка текстово показує Width/Height/Radius/Border/Colors обраного шару без потреби у скріншоті.

Однак:
1. **Знімок екрана (screenshot) полотна Figma технічно неможливий у цьому середовищі** — підтверджено контрольним тестом: знімок звичайної сторінки (example.com) спрацював миттєво, а знімок Figma-полотна послідовно повертає помилку `image readback failed` (полотно рендериться через WebGL, і механізм захвату вкладки розширення не може прочитати цей буфер).
2. **Figma Dev Mode** (який показує точні CSS-значення spacing/типографіки як текст) **вимагає платного оновлення місця** — застосунок показав діалог "Upgrade to work in Dev Mode" із написом "Ask an admin about upgrading", тож детальні токени (padding, gap, font-size конкретних елементів) недоступні на цьому акаунті.
3. Панель **Layers** не розгорталася далі рівня секцій (кліки та клавіша ArrowRight не розкривали дочірні кадри) — тож не вдалося дійти до конкретних кадрів (наприклад, окремо "Dashboard — Populated" чи "Dashboard — Empty") для точнішого порівняння.

**Що вдалося підтвердити достеменно (не вигадано):**
- Секція **"Dashboard"** на сторінці "Ready to Dev" (Desktop): 7576×2197px, radius 2px, border 1px `#000000 10%`.
- На **окремій сторінці "Mobile"** існує **своя секція "Dashboard"**: 11752×3667px — тобто мобільний дизайн Dashboard дійсно існує і не пропущений, поряд із мобільними макетами Clients, Products/Services, Competitors, Marketing channels, Team and Staff, Resources, Risk analysis, Action Plan, MVP, Forecasts & Reports-mobile, Funding & Setup — що збігається зі списком модулів застосунку.
- Кожна із цих секцій — це велика "полотнина" з кількома варіантами кадрів поруч (звідси такі великі розміри), а не один екран.

**Наслідок:** жодної розбіжності "Figma проти живого UI" не включено до розділу UI-багів нижче, оскільки жодну не можна підтвердити на рівні точних значень (кольори в hex, конкретні px відступів конкретних елементів) — це б порушило правило "ніколи не вигадувати баги". Замість цього нижче наведено **виключно ті UI-дефекти, які підтверджені безпосередньо в живому DOM/скріншотах** (наприклад, повторення однієї й тієї самої іконки на двох різних віджетах — це видно і підтверджується без потреби звертатися до Figma взагалі).

**Рекомендація на майбутнє** (перенесено з попереднього звіту, досі актуальна): для справжнього пікселного порівняння потрібен або оновлений платний доступ до Figma Dev Mode на акаунті тестувальника, або заздалегідь експортовані PNG/SVG-кадри конкретно для Dashboard (Desktop + Mobile, populated + empty).

### Bug #2 — Вісь Y графіка "Revenue vs Expenses" відображається як "₴150000k" замість "₴150M"

**Priority:** High
**Severity:** Major
**Environment:** Production, https://frontv2.getlaunched.io, Desktop 1440×900, проєкт "Dior Brand" — відтворюється і на Dashboard, і на Financial → Forecasts & Reports

**Steps to Reproduce:**
1. Відкрити Dashboard проєкту "Dior Brand" → віджет "Financial overview" → міні-графік "Revenue vs Expenses".
2. Прочитати підписи осі Y.
3. Перейти на Financial → Forecasts & Reports → графік "Revenue vs Expenses" (повнорозмірний) і повторно прочитати підписи осі Y.
4. (Для підтвердження) Витягнути текст напряму з DOM: `Array.from(document.querySelectorAll('svg text')).map(t => t.textContent)`.

**Actual Result:** Підписи осі Y буквально: `₴0`, `₴150000k`, `₴300000k`, `₴450000k`, `₴600000k` — без розділювача тисяч, із суфіксом "k", доданим напряму до вже 6-значного числа, що читається як "150 000 тисяч" замість коректних "₴150M".

**Expected Result:** Підписи мають бути у форматі, консистентному з плитками статистики на тій самій сторінці (наприклад, "Initial Investment (CAPEX) ₴4.18M") — тобто "₴150M", "₴300M", "₴450M", "₴600M", або принаймні "₴150,000K" з розділювачем.

**Screenshot:** `screenshots/2026-08-07-dashboard/06-forecasts-reports-axis-bug.png`

**Figma reference:** Не застосовується — числове форматування є даними застосунку, не питанням дизайну; дефект підтверджений напряму через вміст DOM, а не порівнянням з макетом.

**Recommendation:** Виправити форматер підписів осі (ймовірно, повторне ділення на 1000 або відсутня перевірка "чи слід перейти до M замість k"). Записано в `BUG_PATTERNS.md`. Пріоритет High, оскільки цей графік бачить кожен користувач на Dashboard і на головній фінансовій сторінці — сама помилка форматування підриває довіру до фінансових цифр, хоча самі плитки CAPEX/OPEX/Break-even/Profitability залишаються коректними.

## Accessibility

### Bug #3 — Модальне вікно "Add team members" генерує два ARIA-порушення при відкритті

**Priority:** Medium
**Severity:** Minor
**Environment:** Production, https://frontv2.getlaunched.io, Desktop 1440×900, обидва проєкти ("QA Empty State" і "Dior Brand")

**Steps to Reproduce:**
1. Відкрити Dashboard будь-якого проєкту.
2. Відкрити консоль браузера (DevTools).
3. Натиснути кнопку "Invite".
4. Прочитати консольні попередження, що з'являються одразу після відкриття модального вікна.

**Actual Result:** Консоль щоразу показує два попередження:
1. `Warning: Missing 'Description' or aria-describedby={undefined} for {DialogContent}.`
2. `Blocked aria-hidden on an element because its descendant retained focus... Element with focus: <button ...>` — елемент з фокусом залишається всередині контейнера, позначеного `aria-hidden="true"`.

**Expected Result:** Діалогове вікно повинно мати доступний опис (`DialogDescription`/`aria-describedby`), і жоден елемент, що утримує фокус клавіатури, не повинен перебувати всередині дерева з `aria-hidden="true"` — це порушення специфікації WAI-ARIA.

**Screenshot:** Не застосовується (дефект консольний/семантичний, не візуальний) — підтверджено через `page.on('console')`.

**Figma reference:** Не застосовується.

**Recommendation:** Додати `DialogDescription` (навіть порожній/приховано для зрячих) компоненту модального вікна Invite; переконатись, що оверлей коректно знімає фокус перед застосуванням `aria-hidden` до фонового вмісту. Перевірити, чи інші модальні вікна застосунку (Create Client, Create Risk тощо) мають той самий шаблон. Записано в `BUG_PATTERNS.md`. Функціонально вікно працює коректно (форма використовується, закривається через Cancel/✕/Escape, подвійний швидкий клік не створює дублікат вікна) — це виключно питання доступності.

# UI/UX Observations

- **Матриця "Products purchased by customers" на мобільному коректно адаптується.** На 390px ширина показує лише колонки-абревіатури (A/B), а повні назви сегментів клієнтів (A/B/C/D) винесені в легенду під таблицею; сама таблиця має власний внутрішній горизонтальний скрол (`overflow-x-auto`, підтверджено через DOM — `scrollWidth: 512` проти `clientWidth: 302`), що дозволяє прогорнути та побачити колонки C/D. Це — навмисне, робоче адаптивне рішення, **не дефект**.
- **Немає горизонтального переповнення сторінки на жодному з двох проєктів на 390px** (`document.documentElement.scrollWidth === clientWidth === 390`, підтверджено програмно).
- **Область контенту Dashboard прокручується всередині внутрішнього `<main>`**, а не документа (як і зафіксовано в попередньому звіті) — це деталь реалізації SPA-каркасу, важлива для будь-якого майбутнього автоматизованого скріншот-тестування Dashboard, не дефект.
- **Порожній стан Dashboard добре спроектований і послідовний**: однакова структура картки для кожного віджета (заголовок → підзаголовок → ілюстрація → підказка), консистентна типографіка й відступи на обох viewport — за винятком помилки з іконкою (Bug #1 вище).
- Продукт "Eau de Parfum Dior — Signat..." у матриці "Products purchased by customers" зустрічається двічі (рядок з усіма нулями та рядок зі значенням 4642) — це вже раніше підтверджений дефект **"Duplicate Products From Non-Idempotent, Unmarked Test Fixtures"** з `BUG_PATTERNS.md`, повторно спостережений, новий запис не створювався.

# Потенційні ризики

- **Довіра до фінансових даних.** Хоча самі цифри (CAPEX/OPEX/Break-even/Profitability) точні й узгоджені між Dashboard і Forecasts & Reports, неправильно відформатована вісь графіка (Bug #2) може змусити користувача сумніватися в точності всієї фінансової моделі — це видима, а не прихована помилка.
- **Доступність.** Два ARIA-порушення в модальному вікні Invite (Bug #3) наводять на думку, що інші модальні вікна застосунку (Create Client, Create Product, Create Risk тощо), імовірно побудовані на тому самому Dialog-примітиві, можуть мати той самий шаблон — варто провести окрему цільову перевірку доступності по всьому застосунку.
- **Гігієна тестових даних продовжує зростати.** Кількість "сирітських" тестових проєктів в акаунті зросла з 5 (на 06.08.2026) до 7 на сьогодні; а дублікати записів тепер підтверджені вже в трьох модулях (Products, Action Plan, Risk Analysis) замість одного. Без переходу на одноразові проєкти для важких тестів цей список продовжуватиме зростати з кожною сесією.
- **Передчасний висновок про виправлення sidebar-дефекту.** Хоча "Assist me" показав переконливі 5/5, для Notifications і Language вибірка становила лише 1 спробу — недостатньо для остаточного висновку "Fixed". Рекомендовано повторити перевірку (5+ спроб на кожен контрол) у наступній сесії, перш ніж закривати цей запис у `BUG_PATTERNS.md`.
- **Пікселеве порівняння з Figma залишається неможливим** у поточній конфігурації середовища (немає платного Dev Mode; знімок полотна технічно не вдається). Це означає, що жодна майбутня сесія тестування Dashboard не зможе повністю виконати крок "порівняти з Figma" без зміни інструментарію чи надання експортованих зображень.

# Release Recommendation

⚠️ **Ready with Known Issues (Готово до релізу з відомими проблемами)**

Жоден із чотирьох підтверджених дефектів не є блокуючим для основного функціоналу Dashboard: усі 7 віджетів відображають реальні, коректні дані; навігація, глибокі посилання, модальне вікно Invite та підвиди дропдаунів працюють правильно; фінансові показники точно узгоджені між сторінками; мобільна верстка адаптивна й без переповнення. Однак релізу не можна назвати повністю "Ready for Release" через:
1. видиму, підтверджену помилку форматування на фінансовому графіку (High priority),
2. дефект іконки на першому екрані, який бачить кожен новий користувач,
3. два підтверджені порушення доступності,
4. незакритий крок порівняння з Figma (заблокований середовищем, не забутий).

# Висновок

Як старший QA-інженер, я оцінюю функціональну основу Dashboard як **стабільну й таку, що покращується**: усі віджети, глибокі посилання, узгодженість фінансових даних і мобільна адаптивність пройшли перевірку без нових функціональних дефектів. Найбільш вартий уваги позитивний сигнал цієї сесії — рідкісний випадок, коли раніше підтверджений дефект (масова відмова відкриття "Assist me"/Notifications/Language) **не відтворився**: "Assist me" показав 5 із 5 успішних відкриттів проти 0 з 5 минулого разу. Це варто розцінювати як імовірне виправлення, що потребує ще однієї сесії з більшою вибіркою для Notifications і Language, перш ніж остаточно закривати запис.

Водночас цю сесію не можна назвати "чистою": знайдено дві нові, конкретні, підтверджені через DOM (не лише візуально) помилки — мальформатовану вісь фінансового графіка та переплутану ілюстрацію порожнього стану — а також два реальні порушення доступності в модальному вікні Invite. Жодне з них не блокує основний функціонал, але всі мають бути виправлені до фінального релізу, оскільки вони видимі кожному користувачу на першому ж екрані застосунку.

Найризикованіша область на майбутнє залишається незмінною з попередніх звітів: **гігієна тестових даних**. Дублікати записів тепер підтверджені вже в трьох модулях (Products, Action Plan, Risk Analysis) замість одного, а кількість орфанних тестових проєктів зросла — і жодна з цих проблем не зникне сама без переходу на одноразові (disposable) проєкти для тестів, що створюють дані.

Порівняння з Figma й цього разу залишається офіційно **неперевіреним, а не пройденим** — середовище дозволило дійти набагато далі, ніж минулого разу (реальні структурні факти замість повністю порожнього результату), але точне піксельне порівняння відступів, кольорів і типографіки конкретних елементів Dashboard залишається технічно недосяжним без платного доступу до Figma Dev Mode або заздалегідь підготовлених експортів.
